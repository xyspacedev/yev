# Plan 6: yev1-4b Stage 1c (targeted data, Stage 0 replay, retrain) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the ~22k-row Stage 1c data families and a Stage 0 replay, train Stage 1c once, and choose between Stage 1b and 1c on dev.

**Architecture:** The plan touches six areas:

- **New "planned" Opus mode.** Code decides each item's latent facts, questions, options and gold. Opus writes only
  the state text that makes those facts true. A blind check confirms the gold follows from the text.
- **Reuse of the document pipeline.** The mode lives in `src/yev/generators/llm/planned.py` and reuses the document
  pipeline's later steps unchanged: check, no-document control, difficulty.
- **Family planners.** One module per spec cluster under `src/yev/generators/llm/targets/`.
- **Rule-only families.** New modules in `src/yev/generators/`, registered in `RULE_GENERATORS`.
- **Replay.** The mix builder gains a block-level `repeat`.
- **Recipe, config and runbook.** A Stage 1c recipe and config, plus a controller runbook. The runbook runs the
  writers as a workflow, then the GPU steps.

**Tech Stack:** Python ≥ 3.11, uv, pytest. Opus writer/checker and Haiku control subagents use the existing `yev synth`
file protocol, orchestrated by the Workflow tool. Training is unchanged (torch, transformers 5.x, peft).

**Spec:** `docs/superpowers/specs/2026-10-08-yev1-stage1c-design.md`. It builds on
`docs/superpowers/specs/2026-10-02-yev-4b-stage1-design.md`.

**Design inputs (local, git-ignored):** `data/gap_reports/gap_{rjudge,dyna_jev,workflowevals,dev}.md`. Implementers
read the named section for a family's latent variables and hard negatives. **Nothing from these reports may be pasted
into a writer prompt.** Planners encode the pattern in our own words and our own vocabulary lists.

## Global Constraints

- **DecideBench test is never inspected or used.** No task opens `data/bench/decidebench/rows_*` or
  `data/bench_results/**/decidebench*`.
- **Benchmarks are reported as tuned-on.** JevBench, R-Judge, DynaBench and WorkflowEvals failures informed this
  data, and the yev1 card reports them as *tuned-on*.
- **Writers never see benchmark text.** The same goes for benchmark names, question wordings and option
  descriptions. Every question and option description in a planner is our own wording.
  - The contamination filter (`yev filter` with the benchmark fingerprints) runs over every new row.
  - A row whose question copies a benchmark's wording is dropped; that counts as a planner bug, not a filter
    problem.
- **No arithmetic.** No question asks the model to sum, multiply, or count days between dates. Where a decision
  depends on a number comparison, the state prints the computed delta or flag, or both numbers sit side by side
  for a direct comparison.
- **Labels come from code** (planner or rule generator). Opus never sets a gold.
  - A planned question survives only if the blind Opus check (1 sheet) returns the planner's gold.
  - A planned question is then dropped if the Haiku no-document control guesses it 3 of 3 times.
  - Score questions are never dropped by the no-document control.
- **Contrastive groups stay whole.** All states of a group share one `cluster_id` and therefore one split. A
  contrastive group (2+ states) is dropped entirely if any of its questions fails the blind check.
- **Licence and source.**
  - Planned rows: source `synthetic_planned`, licence `yev.generators.common.SYNTH_LICENCE`.
  - Rule rows: source `synthetic_rules`, licence `yev.generators.common.SYNTH_LICENCE`.
- **No uploads.** The box host, key and instance id never enter the repo. Scripts read `YEV_TRAIN_HOST` and
  `YEV_TRAIN_KEY`.
- **Training recipe** is Stage 1b's exactly: LoRA r64/α128, lr 1e-4 cosine, 1 epoch, `n_max` 10, `token_budget`
  12,288, `split_oversized_units` true.
- **Existing mixes build byte-identically.** Recipes without `repeat` produce the same output as before the change.

## Rulings (deviations from the spec)

1. **"50% canonical option order" is dropped.** `yev.format.ordered_options` already shuffles every choice row's
   options at render time, so the model never learns a fixed letter.
   - The WorkflowEvals collapse was onto a *key* (`extra_unapproved`, `none`), which the fixed order made look like
     a letter.
   - The fix is content: hard negatives for those keys.
   - Cost if wrong: a residual letter preference under fixed-order serving. The position-bias check would still
     show it.
2. **Question wording is ours, never the benchmark's.** The R-Judge report suggests using the "production question
   75%" of the time, but that is the benchmark's own wording, which would also trip the contamination filter.
   - Each planner instead carries 4–6 wordings of its own, and the first is used 50% of the time.
   - Cost if wrong: slightly weaker transfer to that exact phrasing.
3. **`agent_benign_multistep` is planned as 2-state groups.** Each group is a safe trace on an alarming topic plus a
   twin where the agent takes the risky step. A one-label family would be removed wholesale by the no-document
   control (always-"no" is guessable). Rows stay ~1,000, now 50/50.
4. **Planned rows get their own source, `synthetic_planned`.** `mix.holdout_key` groups `synthetic_opus` rows by
   writer batch, which would make a whole planned family one holdout unit.
5. **qasper's 600 new rows come from raising its cap.** The cap in `src/yev/sources/public_long.py` goes from 400 to
   1,000, with the existing 400 kept as a prefix. A "new pool" isn't needed; the dataset has far more questions than
   we used.

## Review Focus

1. **Every copy of a repeated row must be its own training unit,** never merged with its original in one microbatch,
   and never in dev or calibration. Test: `test_repeat_copies_are_separate_train_units` (Task 1).
2. **A contrastive group must never be split between train and dev.** If one state fails the check, the other
   state must be dropped too. Tests: `test_planned_group_shares_split` (Task 1) and `test_contrastive_group_dropped_if_any_question_fails` (Task 2).
3. **A writer that returns a state for an unknown gid/sid, or twice, must not create rows,** and must not attach
   another group's questions. Test: `test_ingest_rejects_unknown_and_duplicate_states` (Task 2).
4. **A planner whose label distribution drifts** (e.g. all-"no") passes unit tests but wrecks calibration. Test:
   `test_family_label_balance` (each planner task) checks each family's gold shares over 500 planned groups
   against its table value ±5 pt.
5. **Benchmark text leaking through planner vocabularies.** Test: `test_planner_text_has_no_benchmark_overlap`
   (Task 2). It renders 200 groups per family into writer prompts and question rows, and runs
   `yev.filters.benchmarks.overlaps_any` against `data/bench/fingerprints.json`. It is skipped (with a reason) if the
   fingerprint file is absent.

### Task 1: Mix `repeat` (Stage 0 replay)

**Files:**
- Modify: `src/yev/mix.py` (`build_mix`: after `taken` is computed)
- Test: `tests/test_mix_repeat.py`

**Interfaces:**
- Recipe block fields:
  - `"repeat": float` (≥ 0, default 0). It adds `int(repeat)` full extra copies of the block's train rows that pass
    the filter, plus a further fraction `repeat - int(repeat)` of those rows' units, chosen with
    `random.Random(f"{seed}:{name}:repeat")`.
  - `"repeat_filter": {"family": [...], "source": [...]}` (optional; keys limited to `family` and `source`; any other
    key raises `ValueError`).
  - `"repeat_extra": [{"repeat": float, "repeat_filter": {...}}, ...]` (optional): further passes, each with its own
    filter, applied after the main pass. Pass i uses rng `f"{seed}:{name}:repeat:{i}"` (the main pass keeps
    `f"{seed}:{name}:repeat"`), and copy numbers continue upward so ids stay unique.
- Copies keep the original's train split:
  - `id = f"{d.id}#r{k}"` and `cluster_id = f"r{k}:{unit_key(d)}"`, so every copy is its own unit in `mix.unit_key`
    and in `yev.train.data.unit_of`;
  - copies are appended to `train` only.
- The block report gains `"repeated": <rows added>` only when `repeat` > 0.
- Produces `repeat_rows(taken: list[Decision], block: dict, seed: int) -> list[Decision]`.

```python
REPEAT_FILTER_FIELDS = ("family", "source")


def repeat_rows(taken: list[Decision], block: dict, seed: int) -> list[Decision]:
    """Extra train copies of a block's taken rows: int(repeat) full passes plus a fraction of units.
    Each copy is its own unit (new id and cluster_id), so it never shares a batch with its original."""
    r = float(block.get("repeat", 0) or 0)
    if r <= 0:
        return []
    flt = block.get("repeat_filter", {})
    bad = sorted(set(flt) - set(REPEAT_FILTER_FIELDS))
    if bad:
        raise ValueError(f"block {block['name']}: repeat_filter keys {bad} not in {REPEAT_FILTER_FIELDS}")
    want = {f: set(v) for f, v in flt.items()}
    units = _units([d for d in taken if all(getattr(d, f) in v for f, v in want.items())])
    keys = sorted(units)
    whole = int(r)
    out = [_copy(d, k) for k in range(1, whole + 1) for key in keys for d in units[key]]
    frac = r - whole
    if frac > 0:
        rng = random.Random(f"{seed}:{block['name']}:repeat")
        pick = list(keys)
        rng.shuffle(pick)
        chosen = sorted(pick[:round(frac * len(pick))])
        out += [_copy(d, whole + 1) for key in chosen for d in units[key]]
    return out  # repeat_extra: loop the same body over block.get("repeat_extra", []), see Interfaces


def _copy(d: Decision, k: int) -> Decision:
    return replace(d, id=f"{d.id}#r{k}", cluster_id=f"r{k}:{unit_key(d)}")
```

- **Writer output:** one JSON object per line, `{"gid": str, "sid": str, "state": str}`, and nothing else. The
  writer never returns golds or questions.
- **Rows built at ingest:**
  - `id = f"plan:{run}:{family}:{gid}:{sid}:{qname}"`
  - `cluster_id = f"plan:{run}:{family}:{gid}"`
  - `source = SOURCE`, `licence = SYNTH_LICENCE`
  - `metadata = {"family_mode": "planned", "gid", "sid", "skill", "question_name", "est_tokens", "questions_written"}`.
    `questions_written` counts the group's total planned questions, so `keep_docs`-style accounting works per group.
- **Ingest drops, each counted in the report:**
  - an unknown gid/sid;
  - a duplicate (gid, sid), where the first is kept and the second counted;
  - a state outside `family.tokens`;
  - an empty state.
- **The writer prompt contains:**
  - the family `description` and `state_format`;
  - for each group: the scene, and for each state its brief, length range and the questions it must support
    (question text and options, **without golds**);
  - these rules:
    - make every brief fact true and visible in the state;
    - never state the verdict or use label words ("unsafe", "violation", "correct answer");
    - invent all names;
    - no arithmetic left for the reader;
    - states of one group share the scene and differ only where the briefs differ.
- **CLI:**
  - `yev synth planned-plan --family NAME --groups N --seed S --dir RUN` writes `batches/planned-batch-XXX.json` and
    `.prompt.md` per batch.
  - `yev synth planned-ingest --dir RUN` writes `ingested.jsonl` and `reports/ingest.json`.
  - A planned run counts as a document run for `check-prepare`, `check-score`, `nodoc-*` and `diff-*`, so those steps

### Task 9: Run it (controller runbook)

1. **Pilot, laptop and Opus only.** For each of the 13 planned families: `yev synth planned-plan --groups
   <2 × per_batch> --seed 900`, two writer batches as a workflow, then `planned-ingest`, `check-prepare` /
   `check-score`, and `nodoc-prepare` / `nodoc-score`.
   - **Exit check:** per family, ingest keeps ≥ 90% of states, blind-check survival is ≥ 70% of questions, and the
     no-document drop is ≤ 30%.
   - Read 5 states per family by eye: the brief facts must be visible, no label words, no arithmetic left to the
     reader.
   - Fix the planner or prompt and re-pilot any family that misses.
2. **Rule families:** `yev gen-rules --family <name> --clusters <n> --seed 0` for the four rule families. Then
   `yev filter` with the benchmark fingerprints into `data/stage1c-pool/`.
3. **Full generation,** as one workflow per spec cluster (A–D). Order: A, then D, then B, then C, because A and D
   carry the largest measured losses.
   - Each workflow runs: writers (Opus), ingest, blind check (Opus, 1 sheet), no-document control (Haiku, 3
     samples), difficulty (Haiku, weight 1.5 on misses).
   - Seeds: 0 for the full runs; the pilot's 900 is never reused.
   - Then `yev filter` with the benchmark fingerprints, then copy `final/*.jsonl` into
     `data/stage1c-pool/<family>.jsonl`.
   - **Exit check:** each family reaches ≥ 85% of its row target. Report shortfalls; do not top up silently.
4. **Group E.**
   - Rebuild `public_long` with the new qasper cap into `data/stage1c-pool/public_long.jsonl`.
   - Run the existing document pipeline for ~110 `long_workflow` documents with seed 7. The arithmetic and temporal
     skills are excluded the same way as in `scripts/stage1b_prune.py`. Output goes to
     `data/stage1c-pool/long_workflow_more.jsonl`.
5. **Build the mix:** `yev mix --recipe recipes/stage1c.json --out data/mix/stage1c`.
   - **Exit check:** the mix report shows each new block's train/dev/calibration counts and the `repeated` counts.
     Estimated train tokens fall in 120–140M; report the actual figure.
6. **Ask the user before starting the GPU.** Report the token count, the estimated hours and the cost.
7. **GPU, after the user's go.**
   - Start the Stage 1 box (us-west-2) and sync the code and data.
   - **Check A:** `yev eval` of the yev0 adapter (`~/yev0-adapter`, `~/yev0-calibration.json`) on
